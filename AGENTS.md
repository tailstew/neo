# NEO — notes for agents

NEO is a local word processor for books. It is an Electron app made of plain JavaScript, HTML, and CSS. There is no bundler, no framework, and no compile step. `npm start` runs `electron .`.

Read [CONTRIBUTING.md](CONTRIBUTING.md) before adding a feature. The product is opinionated on purpose. A change that helps someone finish a book belongs here. A change that adds a panel, a prompt, or a dependency usually does not.

## Rules that override convenience

- Nothing interrupts a writer mid-sentence. No popups, no squiggles, no notifications while typing. Spellcheck is off until the writer asks for a pass.
- Controls stay hidden until hover or keyboard focus.
- Words are never discarded. Deleting text, unbinding a shelf, or losing a trash operation must leave the words recoverable (Darlings, a sibling chapter, or the system trash). `book:delete` uses `shell.trashItem`. If trash fails, leave the folder and show it.
- Books are plain files. No database, no proprietary format.
- The renderer never touches the filesystem. Disk access goes through `window.neo` (`preload.js`) to handlers in `main.js`.
- Do not save UI decoration into chapter HTML. Search highlights, spellcheck underlines, and focus dimming use the CSS Highlight API so they stay out of the file.
- Do not rewrite a chapter that has not changed. Libraries are synced with iCloud and Syncthing. A timer that writes every chapter on an interval will fight the other device.

## Writing History

NEO records how each chapter was written, keystroke by keystroke, so the writing can be replayed: every change to a chapter's HTML with its cause, plus keys, caret, clipboard and focus (RECORDING in `app.js`; the plan is `docs/neo-recording-plan.md`). One setting with three levels, **File → Record Writing History ▸ Off / Record Only / Record and Timestamp** (and Off / Record only in Pocket's ⋯ sheet; History itself has no setting): `setHistoryLevel`, kept as `library.recordWriting` and `library.proveWriting` so an older NEO reads the same (`historyLevel()` reads it back). Nothing records until the writer has chosen (`library.historyAsked`): first run's last step asks a new library, and `askHistoryLevel` asks a library from before Writing History once, on the shelf, with no way to put it aside; one answer serves every device that shares the library. The choice made there is the consent, so Record and Timestamp asks nothing more; picked from the menu, it asks first (`proofConsent`). Nothing is sent anywhere, unless the writer chooses timestamping (Proof of when I wrote, below), and then only fingerprints. Pocket records and plays too, through the same code (Pocket, below); a web view without `CompressionStream` (iOS before 16.4) does neither.

- Every change to `chapterHTML` goes through `setChapterHTML` / `dropChapterHTML` with a cause. Typing is one splice (`Rec.splice`, placed by the caret); NEO's own moves, made all at once, are a splice per run of paragraphs they changed (`Rec.splices`), so a name replaced on the first page and the last isn't the chapter between. A key whose change spans more than one run of paragraphs (the junk spans `stripJunkSpans` takes out when a chapter opens are saved with the next key) is split the same way: an `x tidy`, a splice per other run, then the run at the caret as the key. `rec.reconcile` at the top of `persistChapter` logs anything else as `unobserved`, then a `w` line with the hash of the exact bytes. The lines go to disk as a chunk from `flushAllSaves` (every 20 s, blur, hide, close), so a crash can leave a chapter up to 20 s ahead of the recording; the next session's `b` line catches it up. A chunk keeps only each chapter's last `w`.
- The book's other writing is recorded as streams, ids no chapter can have (`Rec.STREAMS`): `:notes` (notes.html, typed in the Notes tab: keys and splices as a chapter's, but no caret), and `:titles`, `:outline` and `:stickies`, JSON as `Rec.streamTexts` writes them from `book.json` and `stickies.json`. They take a chapter's `b`/`e`/`w` lines. `rec.streams(cause)` records what changed in the JSON ones since it last looked; `saveMeta` and `writeStickies` call it with a `w`, and a site that knows its cause (merge, delete, undo, another device) calls it first. Write `stickies.json` through `writeStickies`. Streams are in no `o` line, no word stats, no day map and no search, and the player doesn't play them (`Rec.isStream`).
- A session is JSON lines: a header, then `[dt, kind, …]` arrays (the kinds are listed at the top of `recording.js`). The header's `neoRec` is the format: change what a line means and it takes the next number, and the old number stays in `READS` with its own branch, because writers keep years of sessions. Readers skip formats they don't know. The header also has `platform` (`navigator.platform`): keys are physical `KeyboardEvent.code`s and Ctrl/Meta as pressed, so a reader that names shortcuts needs it. Ordinary typing becomes `r`/`rd` runs and caret keys `n` runs through `RunEncoder`; `expandRuns` turns them back into one `k` and one `e` or `s` per key. A hash is `digest`: SHA-256 cut to 128 bits, in base64url. Every chunk ends with an `h` line chaining it over the line bytes.
- The first time a session touches a chapter, a `b` line says what it was (`Rec.baseLines`): `continue` (hash only) when it is where this device's last recording left it, `anchor` (all of it again) once the chapter has been edited 200,000 characters, or four times its length, since its last full `b`, `baseline` when it was never recorded; then a `catch-up` if it changed while nothing recorded. The edits are counted in the window (`rec.edited`) and in `known.json`. Anchors bound how much any replay has to play, and are where it picks up after a session went missing.
- `rec:` handlers in `main.js` (and Pocket's bridge), through `recording-files.js`, write only `recording/<device>/` in the book: a `c-<line>.jsonl` chunk per flush, an `s-<first>-<last>.jsonl.gz` rollup every 10 minutes (read back before its chunks are deleted), and one `<session>.jsonl.gz` when the session closes (book closed, window closed, the writer's day over, setting off). A session is at most a writer's day: `writingDay()`, the goals' day, which ends at `library.dayEndsAt`. Its header says which (`day`). `rec:start` closes any session this device left open, with `["end",{"crashed":true}]`. No file is ever rewritten or appended to.
- Backups: the daily zip leaves `recording/` out. Each closed session is copied once, byte for byte, into the mirror, `Backups/recordings/<book folder>/<device>/` (`mirrorDevice` in `recording-files.js`): this device's at `rec:close` and `rec:start`, and `dailyBackup` sweeps up the rest at each start, another device's only once it closed more than 7 days ago (`sweep`), so two devices rarely write one file. A copy is never written again. A closed session the book lacks, or holds broken, is read from the mirror (`readClosed`), by the list, the player, the cache and `known`, never copied back. The mirror goes to the trash with its book. Pocket reads the mirror and writes none.
- `replayCheck` is the invariant: replaying the sessions must hash to every `w`. `npm run test:recording` checks it against the chapter files on disk.
- The **Writing History** dialog (WRITING HISTORY in `app.js`, `openHistory`) plays the book's sessions back, every device's: History in the footer (a `.tab` with no `data-tab`, so it never becomes one), **File → Writing History…** (never greyed out: with no book open it says so, as Export does), **Writing History…** on a book's shelf menu, and **Watch This Chapter Being Written** in `chapterMenu`. It reads, except for restore and delete (below). It opens on the days: the chapter the caret is in (or the whole book) as it is now, above a strip of tiles, one per writing day, each with its date and a map of where that day changed the text (`historyMap`: a grid read like a page; in the whole book each chapter a run of cells as long as its share of the words, a line where each begins; from the sessions' bins, `Rec.binsFor`); ← and → show each day as it ended. A tile picked opens the player on that day, with the days before and after as tiles either side of its timeline. The side pane lists the chapters in the book at the moment on the sheet, in its order then (`listedChapters`; the book as it is now until a day is loaded), so they come and go as it plays through a merge or a delete; the one picked stays, dimmed, where it isn't there. The day is the unit: the player loads one (`historyLoadDay`: its sessions, played by `Rec.History` from the day's start state) and plays on into the next. Nothing plays until the writer presses Play (or Space): a day picked, and Watch This Chapter Being Written (`firstDay`), open the player paused. Esc in the player goes back to the days, and a click outside the dialog closes it. The player's controls are ▶/❚❚ (as written, 1×) and ▶▶ (`HISTORY_FAST`, 8×); a pause longer than 1.5 s plays 1.5 s at ▶ and is skipped at ▶▶, and either way a badge says how long it really was (the exported page too, `rx-badge`). The player's clock starts at its first moment (`Rec.playFrom`): after the steps that only say what was already there (`Rec.leadSteps`: a `baseline`, a `catch-up`), and, where the chapter shown (or any chapter, in the whole book) isn't there yet, after the step that brings it, so a day opens on words, never on an empty page; the play head can't go before that moment or past the day's last. The exported page does the same. A paste from elsewhere in the book is marked on the timeline as moved text. Its footer holds the moment shown ("Your book …") and, once the book has seals, when the text at that moment was first timestamped ("Timestamped …", `stampedBy`), then **Tag This Moment…** and the chapter's restore beside it, then How It Was Written…, Export and Delete, every one the same pill button (`.hs-foot button`). When the book was last timestamped (`proofSays`) is a toast as the dialog opens, not a line in it. Under the timeline's bars a track has a dash at each timestamp, where in the day its seal reached (`stampTrack`). Both come from `rec:stamps` (`stamps` in the history worker): for each of the day's sessions, the `h` line each seal names, with the time it was first stamped (a seal not stamped itself takes the next stamped one's). Desktop only. While it's open the menus stay live: a menu item clicked closes History and then does what it says (`onMenu`), but one reached by its shortcut does nothing behind it (`markShortcuts` in `main.js` marks such a message `byKey`). Find and ⌘S stay the dialog's own: `ui:modal` tells main it's open, so ⌘S reads Tag This Moment….
- Devices merge into one page (`Rec.Page`). Each device plays its lines onto its own copy of each chapter, since a `continue` means where *that* device's recording left it; the page is the very `ChapterText` of the device that last changed each chapter. A change from another device takes the page over, and is a sync (a step's `sync`, the device's copy as it was, marked "As it was on …") when that copy isn't what the page showed. Changes in `Rec.QUIET` (`continue`, `anchor`, `baseline`, `catch-up`, `disk-adopt`, `disk-new`) leave the page alone (`page: false`) unless it already shows that copy, until their run ends somewhere the page isn't (`settle`); they are nobody's words in the stats. A day's sessions play a line at a time in wall-clock order (`Rec.interleave`), so NEO open all day on one computer interleaves with a session on another. `History` (steps) and `linePlayer`/`sessionPlayer` (lines, in the worker) both drive `Page`, so the player, the cache and search see the same page; keep them in step.
- Search (the field atop the dialog's side pane, ⌘F/Ctrl+F there) finds when a phrase was first written, last written, written out and moved. Two toggles in the field (shown on hover or focus) set **Match case** and **Whole words only**: the search is `{ text, word, cs }` (`Rec.phraseQuery`; a string means whole words, any case), and those defaults last while NEO is open (`historyFindOpts`). `rec:search` answers with a pass over the cache's day states (`Rec.phraseDays`), then the worker looks inside the days that pass can't see into (`searchWithin`) and posts what it finds as `rec:progress`; `rec:searchStop` stops it. A finding picked opens its day and stops at the moment it means (`Rec.phraseEvents`, `Rec.phrasePick`), with the phrase highlighted (`neo-replay-find`). Search looks at the moments the recording states a chapter's text: each `w`, each `b` that sets it whole, and every session's end. It writes nothing.
- A click on the player's sheet picks the paragraph under it (a selection, the paragraphs it runs through), highlighted (`neo-replay-part`). While paused, buttons float in the sheet's margins beside it (`renderPart`, kept in sight as it scrolls): ‹ (or [) and **Restore This Paragraph** on the left, › (or ]) on the right, go to the time before and the next time it changed (`partGo`), or restore it; where the window leaves too little margin, restore is ↺. Where it isn't in the text at that moment, the badge says so instead. Esc, or a click off the text, puts it down. A part is offsets a…b of the chapter's HTML, carried through each splice (`Rec.partThrough`, `partMove`); its changes come in bouts, a run of changes to it with nothing changed elsewhere between, and each stop is where a bout ended (`Rec.partNext`, `Rec.partPrev`). It goes back as far as it was first written (a part whose words all came in one splice wasn't there before it) and on as far as it was taken out; an edit that replaced paragraphs is matched a paragraph at a time, as a change made all at once is. Across days, the cache's day starts say which days changed it, and only those are loaded. Once the player stops, ‹ and › look ahead (`probePart`), and a way with nothing is off. In the days, a click opens the player at that day's end with the paragraph picked.
- Tags ("tags" in WRITING HISTORY, `Rec.tagsOf`): a name on a moment, one `tag` line. `rec.tag(label, at, made)` writes it in the session being recorded and flushes at once, returning the moment its line is on. NEO's own have label `null` and `made` (`{ snapshot: folder }` from `takeSnapshot` while recording, `{ restore: moment }` before a History restore) and are named when shown (`tagName`). A moment is `[session, line, device]` (`Rec.momentStep` finds it in a `History`); in a tag's `at` it also carries its ISO time. A later line with the same id renames it, or removes it with label `false`. Tags are in each session's stats (`stats.tags`), so the cache lists them. **Tag This Moment…** in the footer beside restore, or ⌘S in History (the `snapshot` menu message goes to `historyShown.tag`), only while this book is open and recording. Shown as Tags in the side pane (right-click renames or removes), flags on the timeline and the tiles, and in search by name.
- Restore (`historyRestore`): the button in the footer, while paused or in the days, takes the chapter played (in the whole book, the paragraph picked's, else the caret's) back to that moment, at once, in the snapshot view's words (**Restore This Chapter**, **Restore Paragraphs**, **Put This Chapter Back**). What it replaces is kept first, never in Darlings (`historyKeepBefore`): while the book records, a tag on the moment just before (`made: { restore }`, "Before restoring to {when}"), on disk before anything changes; otherwise, or if that write fails, an `r` snapshot as a snapshot restore takes; if neither can be kept, nothing changes. The toast says where. A chapter still in the book gets the old HTML with cause `restore`; a deleted one comes back as a new chapter after the one it followed then, with its title then. Each takes a `snapshotStructure`, so ⌘Z undoes it, and the `x restore` line names the moment (`session, line, device`). A book that isn't open is opened first, the one thing a restore asks (`opensFirst`). Picking a deleted chapter shows it in the days as it was just before it went. The paragraphs picked on the sheet have their own button beside them, which restores only them (`restoreParagraphs`): `trackToNow` carries them to the book as it is, through the rest of the day a step at a time, through later days a day's end at a time in the worker (`rec:track`, `Rec.partDays`, over the cache's day states), then to the chapter now; where that loses them it looks for their words in every chapter (`Rec.findParagraphs`). Found in their chapter, they're replaced (`historyRestoreParagraphs`, kept first in the same way, one ⌘Z); not, the dialog says whether they were taken out, their chapter deleted, or they seem to be in another chapter, and offers to copy them, or put them in Darlings and copy them, as they were. Text copied from the sheet is remembered (`rec.copiedFrom`), so its paste is `internal` and carries the moment too. **Delete this book's history…** in the footer asks with `confirmModal`, which says what goes (the tags, with their number) and what stays (the book, its snapshots) and won't go on until the writer types the phrase it shows ("delete history", in the interface's language); then it ends the session, then `rec:delete` moves `recording/` and its mirror to the system trash (a folder the trash won't take stays, shown) and drops the cache; recording starts again from a baseline. Pocket has no `recDelete`, so it hides the button.
- The cache is built by `history-worker.js` (`rec:days`, `rec:dayStart`, progress as `rec:progress`) from every device's folder into `userData/recording-cache/<book>/`: `days.json.gz`, an index with every session's and day's stats, and `day-<day>.json.gz`, each chapter the day changed on the page and on each device that wrote that day, whole or as a paragraph diff (a device's copy that was the page's is `{ page: 1 }`). Never in the library. A session another device left open on an earlier day is built with its day, and built again once it closes. Chapters are held as paragraphs in a Fenwick tree (`Rec.ChapterText`), so a splice in a 300 KB script copies one paragraph.
- These are format changes too: counting a caret over anything but `Rec.CARET_BLOCK` (`recPoint`, `historyPoint`), renaming an `INPUT_TYPES` code or a `MOD` bit, or a new line kind. A change to what `compileSession`, `History`, `playSession` or `DayBuilder` make of the same lines raises `PLAYER`, so the cached days are rebuilt. `scripts/recording-format.test.js` reads the frozen sessions in `scripts/fixtures/recording-v1/` and fails on any of these; never regenerate a fixture to make it pass, and add a `recording-v<N>/` for each new format. The fixtures are `-text` in `.gitattributes`: their hash chains cover the exact bytes.
- The player's sheets are `.rp-chapter` / `.rp-body`, never `.chapter` / `.chapter-body`, so the recorder and the editor's handlers ignore them; the manuscript's rules in `styles.css` reach them through `:is(.chapter-body, .rp-body)`. Old sessions are drawn with today's CSS, so a class chapters once held keeps a rule there after the editor stops writing it. The text looks just as it did in the editor: nothing is tinted or struck through. Its caret is a mark in the copy of the HTML it draws, and a selection is the CSS Highlight API. A sheet is drawn a paragraph at a time (`drawBody`): it remembers the nodes each `ChapterText` piece made and replaces only the pieces that changed, so keep it the chapter's elements side by side, with no wrapper per paragraph.

## Proof of when I wrote

The level **Record and Timestamp** (`library.proveWriting`, Writing History above), desktop only, and only while recording. The plan is part 2 of `docs/neo-recording-plan.md`.

- `proof.js` writes `recording/<device>/seals/NNNNNN.json`: `{ neoSeal: 1, seq, at, book, device, publicKey, after, heads, others, tokens, prev, sig }`. `heads` is the last `h` of every session changed since the last seal, the open one's too; `others` (`{ <device>: { <session>: h } }`, when there are any) the same for each device that seals nothing of its own (Pocket, a computer recording without timestamps), every `h` no device's seal names yet, as it reached this computer by sync (`Sealer.others`), so a phone's writing is fixed in time by when it arrived; a NEO from before `others` checks the seal whole and ignores it; `after` a drand quicknet round, asked before `at`, left out when nobody answers; `tokens` the SHA-256 of each stamp written since the last seal, so a newer seal's stamps cover older ones; `prev` the hash of the previous seal's bytes; `sig` Ed25519 over canonical JSON. Beside it: `NNNNNN.<tsa>.tsr` (the authority's whole TimeStampResp). Every file is written once.
- When (`proofRun` in `main.js`, one call at a time per book): once the writing stops, five minutes after the last chunk that wrote words (a `w`, `d` or `tag` line; `proofWrote`), so a seal, and its dash on History's timeline, comes at the end of the stretch it covers, or at once when the first unsealed words are an hour old; when a session closes with words unsealed (a chunk of caret moves and focus alone seals nothing); when the writer names a tag (`rec.tag` calls `proofSeal` once the line is on disk); when proof is turned on; at `rec:start`, a seal of the stamps alone if the newest is 335 days old. At `rec:start` and every half hour, each book whose `recording/` holds another device's folder (`proofOthers`, open or not) is sealed if another device's sessions want it (`seal({ ifOthers: true })`); a book never written on here gets this computer's folder then (`recPrepare`). Only the newest seal is stamped: two of DigiCert, Sectigo and GlobalSign, in that order unless the writer changed it, the next asked when one fails or was asked under 15 s ago (Sectigo's request). Stamps that failed are asked for every half hour. A book opened whose seals have waited more than a week for a stamp says so in a warning toast (`proofWarnStale`, `waitingSince` in `proof:status`, asked once the open's own try is over; not if the writer has begun typing). Nothing here holds up a save, and only a seal's SHA-256 leaves the computer.
- The key is `proofKey` in `userData/secrets.json` (`writeSecret`, `safeStorage`), made at the first seal; `secret:set` refuses that name. The heads of closed sessions are cached in `userData/recording-cache/<book>/heads.json`, by device (only from a chain that verifies whole: another device's file may still be arriving).
- Whatever reads seals reads every device's for each session (`Rec.sealsOver`: its device's by `heads`, another's by `others`): the time cover (`timeCover`, which takes the earliest whatever the order), the player's stamps, the exported page's checks and track, and verify-recording, which checks `others` against that device's sessions (`verifyDevice`'s `others`). The cover lists a device with no seals of its own too, so its sessions count.
- **Timestamp services…** (`openTsaServices` in app.js), opened from **File → Record Writing History ▸ Timestamp Services…** (after Record and Timestamp): the writer's order and on/off of the three, and services they add. The writer's, on every computer: `library.proofTsas`, which the window sends with the proof flags (`proofFlags`, at load, when another device's library is taken, at `rec:start` and when the dialog opens); `proofServices()` in main.js reads what it was last sent, and `proof:services*` change it and hand it back as `keep` for the window to write into library.json. Adding (`proof:serviceTry`, then `proof:serviceAdd` on the writer's yes) makes one test request and finds the service's root (`Proof.findRoot`: a public root it chains to, else the self-signed top of its chain, fetched up its `caIssuers` links if the token doesn't carry it), kept as PEM in the service's entry (`root`). Public means in `proof-roots.pem` or Mozilla's list (`tls.rootCertificates`). Before an added service's first stamp in a book, the Sealer writes its root beside the seals as `seals/root-<16 hex>.pem`, once. `verifyDevice` trusts those only when they're in Mozilla's list; a stamp resting on any other is good, not trusted, and marked `added`. The mirror and the exported page carry the root files.
- Seals and stamps are mirrored into `Backups/recordings/` like closed sessions (`mirrorDevice`), and go to the trash with the history.
- **How It Was Written…** in History's footer (`evidenceHtml` in app.js) shows how the book, or a chapter, was written, in figures only, with no judgements drawn from them: the rhythm of the keys (the gaps between them as coarse bars, split at `Rec.EV_GAPS`), pauses by where the next letter went, revising as typed (deletions where the text was being written, quick fixes, deletions in a row as bars by `Rec.EV_RUNS`, spelling suggestions picked) and later (going back into earlier text, what was typed and deleted with 500 characters or more of the chapter after it), pastes from outside NEO and how soon after coming back to it, changes with no key by kind, words never recorded, and the timestamps (how many, the first and last, the mean time between, the services, the sessions not timestamped within a day). A spelling suggestion picked from NEO's menu is typed by the engine with no key, so `rec.mark('spell')` writes an `x spell` before it; a session from before that line is read by its shape (just after the caret was placed, letters inside a word changed and nothing else). The figures are `Rec.evidence` (played as one `Page`, so another device's recorded words aren't "outside") and `Rec.evidenceRead`, worked out by `rec:evidence` in the history worker, which also checks each device's seals (`proof.timeCover`). Pocket has no `recEvidence`, so no button.
- **Export Writing History…** (`exportReplayAsk`, `rec:export`, `replay-export.js`) writes one HTML file that plays the history in any browser, offline, laid out as the dialog is (`player` in `replay-page.js`): the chapters and the tags down the left (a tag goes to its moment), the sheet, the days as tiles or a day's timeline (the same markers, and the timestamps' track), and a footer always on screen with ▶ and ▶▶ (8×), the moment, when it was timestamped, and **How it was written** and the checks, each in a pop-up (`<dialog>`). Without JavaScript it's the report on a plain page. It checks itself: each session's chain, the replay against every `w` (hashed with WebCrypto), each seal's Ed25519 signature, chain, heads, covered stamps and drand round, that each timestamp token stamps its seal and when, and the report's figures worked out again (in a Web Worker made of its own scripts; the page's CSP allows only its nonced scripts and `blob:` workers). The whole book carries its seals and `proof-roots.pem`; chosen chapters carry only their lines (`Rec.keepChapters`: no `h` lines, the time of lines left out carried on) and no seals, and the page says nothing on it fixes them in time. Its words are `REPLAY_PAGE_WORDS` in app.js, sent in the writer's language; `scripts/replay-page.test.js` fails on a `T('…')` in the page that isn't listed.
- `node scripts/verify-recording.js <book folder> [--online] [--json]` checks every device's chains, `replayCheck`, each seal (signature, chain, heads, covered stamps, `after`, stamps against `proof-roots.pem`), and lists sessions not timestamped within a day. `scripts/proof.test.js` checks real DigiCert and Sectigo tokens in `scripts/fixtures/proof/` offline; never regenerate them to make a test pass.

## Outline cards

The Outline tab shows the book as index cards (OUTLINE CARDS in `app.js`) unless `library.outlineView` is `'list'`. A script's Outline is always cards, one per scene (`scriptScenes`): heading, length in eighths, cast, and a note in `book.sceneNotes`, keyed by `data-scene-id` on the heading line. Dragging a scene card calls `spMoveScene`.

- Cards come from the manuscript, not a separate structure: each chapter is cut at its `p.scene-break` lines (`chapterSegments`). A section that holds a `p[data-sec-id]` belongs to that note in `book.sectionNotes`; the first section to carry an id owns it, because paragraphs split from a written ghost inherit the id. Others show their first line.
- Moving a card moves its paragraphs and *** between chapter bodies, then `syncChapter` and `orderSectionNotes`. Every move takes a `snapshotStructure` first.
- `syncGhosts` leaves a ghost where it stands and places a note the page lacks before the next section that's there. It never reorders ghosts.
- Loose cards are `book.looseCards`, shown in the right-hand pane while the Outline is up. A section card dragged there (or Move to loose cards) goes both ways: a section with writing takes its words along as `card.html`, out of the manuscript and the counts until it's placed again. Chapter cards and a script's scene cards go there too: the card carries the chapter (words, title, notes, kind; `held: 'chapter'`) or the scene's lines (`held: 'scene'`), written to book.json before they leave the page, and comes back whole (a chapter only between chapters). A card's Delete sends held words to Darlings first. A section card's Delete section sends its writing to Darlings (`deleteSectionToDarlings`).
- Several cards at once: ⌘-click (Ctrl-click) toggles a card, Shift-click takes a run, and a drag across empty outline space sweeps (`cardLasso`). The picked cards are `cardSel` (keys from `cardKey`), kept across a redraw and dropped after a move. Delete/Backspace or the right-click menu runs `deleteSelectedCards`: one `snapshotStructure`, the single deletes run quiet, sections and scenes from the last up, and a book keeps at least one chapter.
- `joinChapter` makes a chapter a section of another (List Tab on a chapter line, or a chapter card dropped on the middle of another). It moves the lines, persists the receiving chapter, and only then deletes the emptied one.
- In the List, Enter always makes a chapter and Tab always makes a section.
- On a card made new (`cardEditor.fresh`), Enter with words on it opens the next new card; Enter on an empty one, or Esc, stops. A pasted list (`pastedOutline`: the clipboard's HTML levels from `<ul>`/`<ol>` or Word's `mso-list`, else `outlineLines` on the text) becomes one card per item, and in the List one line per item: on a chapter, top items are chapters and deeper ones their sections. `scripts/outline-paste.test.js` covers the text's markers.
- While writing, the top of the right-hand pane shows the cards for where the caret is (`sideCardsUpdate`, `#side-cards`): the chapter's and its sections' (the caret's marked red), or the script scene's. Typed on there, they're the same notes; a scene gets its id with its first note.
- A script scene's card note shows in gray on the scene's empty first line (`spSceneNoteGhosts`, a `data-scene-note` screen mark that `captureBody` strips).

Brighter Interface is two settings: `library.uiBright` while writing (and on the shelf), `library.uiBrightAside` on the other tabs, bright unless turned off. `applyBright` picks one on every tab switch.
- The walking note (`walkNoteUpdate`) is an overlay inside `.chapter`, plus a `data-walk` mark on the caret's paragraph that `captureBody` strips. `note.dismissed` hides it for good.

## Screenplays

A book whose `book.json` says `"format": "screenplay"` is a script. Right-click (long-press) a shelf's + for New Script. The SCREENPLAYS section of `app.js` holds the feature; `scripts/screenplay.test.js` tests its rules.

- The whole script is one chapter, so selection and the arrow keys run through every scene. Scenes are found by their headings.
- Each line is a `<p>` whose class is its element: `sp-heading`, `sp-character`, `sp-paren`, `sp-dialogue`, `sp-transition`, `sp-shot`. Action has no class.
- Page breaks, page numbers, (CONT'D) and the gray suggestions come from `data-pg`, `data-fill`, `data-contd` and `data-ghost` marks. `captureBody` strips them. Never save them.
- Lengths in `styles.css` are in em of the script's type (51em = 8.5in, 1em = one 12pt line), so a line wraps the same on screen, in the off-screen measuring room and in the PDF. `spPaginate` places the pages from the line counts.
- `data-newpage` on a line is the writer's own page break (right-click → Page Break Here; Backspace at the line's start removes it). Unlike the screen marks it is saved, and it travels as `===` in Fountain and `StartsNewPage="Yes"` in Final Draft.
- A script's style lives in its `book.json`: `underlineHeadings: true` (Format → Underline Scene Headings) and `contd: false` ((CONT'D) turned off).
- A script exports as a PDF (letter, printed with `print: 'screenplay'`), Fountain or Final Draft (`.fdx`). The book formats don't apply.
- A `.fountain` or `.fdx` file dropped on a shelf or picked with Import becomes a new script. `importFile` in `main.js` only reads the file; `spFromFountain` and `spFromFdx` in `app.js` sort it into elements. Both readers are plain string functions, so the tests cover them (`scripts/fixtures/` holds a Final Draft file written by screenplain, an outside tool).

## Paperbacks for KDP

Export → Paperback for KDP… (also on the shelf's right-click Export) writes a print interior PDF and a cover template PDF beside it. `printPaperback` and `buildPrintHtml` are the PRINT BOOK section of `app.js`; `makePaperback`, `renderPaged` and `kdpCoverHtml` are in `main.js`, behind `print:paperback`.

- Trims are KDP's four most-used: 5×8, 5.25×8, 5.5×8.5, 6×9 (`PRINT_TRIMS` in `app.js`, `KDP_TRIMS` in `main.js`). Paper thickness, page limits and the inside-margin bands (`kdpGutterMin`) come from KDP's help pages; NEO adds a quarter inch to the minimum. If the page count crosses a band, the book is laid out again with the wider margin.
- Pages are set by Paged.js (`print/paged.polyfill.js`, vendored, MIT) in one offscreen window per export. A hidden window stalls its animation frames; a second offscreen window opened right after one closes fails. The window closes when the export ends. One patch in it is marked `NEO:` (a word hyphenated across a page turn broke a letter late).
- Hyphenation is soft hyphens put in by `hyphenateHtml` in `main.js` with TeX patterns (`print/hyphen/`, ISC), because Chromium only hyphenates on macOS. Only `p.hy` prose is touched; names (capitalised words, except in German) and a paragraph's last word stay whole.
- Chromium rounds page sizes to 0.01 in; `exactPageBox` rewrites the MediaBox to the exact size in the same number of bytes.
- The page count is kept even. Chapters open on a right-hand page; blank pages carry no head or number.
- Choices are kept: trim, paper, ISBN and fiction notice in `book.print`; on the pen name, `author.print` holds the back-matter links, `alsoByText` (the writer's own list, one title per line) and `reviewText` (own wording, with `{title}` for the book's title; empty means NEO's translated wording). A dedication typed in the dialog becomes the book's own Dedication page.
- Page 1 is the story's first page (the first `chapter` section, so a prologue). In the paperback that section is `.pg1` and each page's number is set on it after layout. The regular PDF stops counting on `@page front` pages and numbers its contents from the `data-p1` link; pages after page 1 that show no number (a part's title) are `.page.counted`.
- `scripts/print.test.js` covers the margin bands, hyphenation, the page box and the cover's size. Pocket has no paperback export.

## Snapshots

⌘S (Ctrl+S; File → Take Snapshot) snapshots the whole book (SNAPSHOTS in `app.js`). NEO also takes one before the first change of each writer's day (`maybeDailySnapshot`, by `writingDay()`, from `scheduleChapterSave` and `snapshotStructure`, built from `savedHTML` so it holds the day's start). While the book records, each snapshot is also a tag in Writing History (`made: { snapshot }`). No timer, and nothing is taken when nothing changed.

- One folder per snapshot, `book-…/snapshots/<UTC stamp>Z-<kind>-<chapters changed>-<words>-<rand>/`, holding only the chapters that changed since the last snapshot and, written last, `snapshot.json` (order, titles, kinds, a `textHash` of every chapter). Files are written once (`snapshot:list/read/write/remove` in `main.js`, the same four in Pocket's bridge). A chapter's text at a snapshot is in the newest snapshot at or before it holding the file (`snapHolder`).
- Kinds: `k` ⌘S, kept until deleted; `d` start of a day and `r` just before a restore, which go after 30 days (`snapsToThin`). A snapshot that goes first copies its chapter files into the next one that lacks them, so later snapshots still read whole.
- The Darlings tab's right-hand pane lists them (and stays open there); picking one shows the book as it was in `#snap-view`, read-only, words gone since marked with the CSS Highlight API (`wordsGone`). Restore This Chapter and Restore Whole Book take an `r` snapshot and a `snapshotStructure` first, so ⌘Z undoes them. A passage can be set aside as a darling from the right-click menu. **Watch from Here** (the shown snapshot's band, and a snapshot's right-click menu, while the book has a history) opens History at the snapshot's tag (`snapWatch`); History has no way back to this list of its own. Pocket takes snapshots but has no list yet.
- The daily backup zip leaves `snapshots/` out. `scripts/snapshots.test.js` covers the names, the fingerprint, thinning, where a chapter's text is and the marks.

## Per device

How NEO looks belongs to each device: `DEVICE_LOOK` in `app.js` (page theme, brightness, zoom, type size, typewriter, focus, counters, outline view, vim keys). Every library write also keeps them in this device's `localStorage`; every library read takes them back from there (`applyDeviceLook`). The library's copy is the last device's, which is what a device new to the library starts with. Zoom is per device and per view: the page per mode, the cards, and the shelf (`neo.shelfZoom`, ⌘+/− and pinch on the shelf), each in `localStorage`; the page moves in tenths. The desktop also keeps its page theme in `settings.json` for the window's color at launch, and `exportFolder` there, so save dialogs open where the last export went.

A book's right-click on the shelf is a small menu (`popMenu`) on the desktop, with the cover's choices one level in; touch keeps the larger cards. Duplicate (`book:duplicate`, and `duplicateBook` in Pocket's bridge) copies the folder under a new id and title, without `recording/`: the copy starts its own history.

Pocket makes PDFs through `NeoPdf`, a native plugin in each project: Android opens its print screen (Save as PDF), iOS draws the pages into a file for the share sheet. A script's title can be set bold, underlined or italic as a whole (`book.titleStyle`, ⌘B ⌘U ⌘I on the title page), and keeps it in the PDF, Fountain and Final Draft.

## Processes

```
index.html + app.js  →  preload.js (window.neo)  →  main.js  →  NEO Library
                                                      ↓
                                               spell-worker.js, history-worker.js
```

The window is created with `contextIsolation: true` and `nodeIntegration: false`. New renderer capabilities are added in three places: an `ipcMain.handle` in `main.js`, a method on `window.neo` in `preload.js`, and the call site in `app.js`.

## Files on disk

Default library: `~/Documents/NEO Library` (`app.getPath('documents')`). **File → Library Folder…** stores another path in `userData/settings.json` and restarts. NEO does not move existing books.

```
NEO Library/
  library.json          shelves, author, pen names, customWords, spellLanguage
  _catalog.txt          regenerated map of folder → title; edits are ignored
  neo-errors.log
  Backups/neo-backup-YYYY-MM-DD.zip    one per day, 14 kept, without books' recording/
  Backups/README.txt    how to restore
  Backups/recordings/<book folder>/<device>/   each closed Writing History session, copied once
  Exports/              emailed PDF snapshots
  book-<slug>-<id>/
    book.json           metadata and chapterOrder
    chapters/<id>.html
    notes.html
    outline.html
    darlings.json
    stickies.json
    cover-<ts>.<ext>    writer-chosen image
    art-<ts>.<ext>      painted image, plus art.json
    recording/          Writing History; README.txt, then one folder per device
      <device>/         device.json, <session>.jsonl.gz, and the open session's folder
        seals/          proof only: NNNNNN.json, its .tsr stamps
```

App settings and the cover-art API key live in Electron `userData` (`settings.json`, `secrets.json`), not in the library. `settings.json` also holds this computer's `recordingDevice` id, `secrets.json` its proof signing key (`proofKey`), and `userData/recording-cache/` holds replays that can always be rebuilt. The key is encrypted with `safeStorage` when the OS allows it. Do not write secrets into the library.

Every book id, chapter id, and sidecar name passes through `libName()` in `main.js`. It allows one path segment and rejects `.`, `..`, slashes, and null bytes. Keep new files inside that helper.

Every library write goes through `writeFileDurable`: `file.tmp`, fsync, then rename into place, so a power cut can't leave an empty file. `writeJSON` also keeps the last version that read whole as `file.bak`, and `readJSON` falls back on `.tmp`, then `.bak`. A `book.json` lost with no copy is rebuilt from the chapter files (`rebuildBookMeta`). There is no append and no partial chapter update.

`json:write` and `aux:write` will create any single-segment `<name>.json` or `<name>.html` in the book folder. Prefer the existing names unless a new sidecar is actually required.

## Saving and sync

The window holds the open book in memory (`chapterHTML`, `book`, `stickies`, `darlings`) and remembers what it last wrote (`savedHTML`, `savedMetaSig`).

- Chapter and notes edits debounce 800 ms, then write only if the HTML changed and the chapter is still in `chapterOrder`.
- `flushAllSaves` runs every 20 s and on blur, hide, and close. It also stores `lastPosition` in `book.json`. A scroll-only change is not a new position.
- `refreshFromDisk` runs on focus, on visibility, and every 30 s while visible. It compares `mtimeMs:size` stamps and re-reads only changed chapters.
- Unchanged local chapter plus a changed file: adopt the file. If the file only has fewer words, adopt it and keep the displaced text in Darlings.
- Both sides changed: keep the local text on the page and insert the disk text as the next chapter, titled as from the other device.
- Skip a chapter whose write is still in flight. Drop a read that overlapped a local save. An empty read must not wipe a chapter that already has text.
- The same generation check applies to `library.json` on the shelf (`libraryGeneration`, `libraryWritesPending`).

Do not replace this with last-write-wins. The comments in `persistChapter` and `refreshFromDisk` explain cases that look redundant and are not.

## Interface language

Wrap writer-visible strings in `t('English text', { placeholder })`. Use `tk()` for strings translated later, at the point of display. In `index.html`, use `data-i18n`, `data-i18n-title`, `data-i18n-placeholder`, or `data-i18n-ph`.

After adding or changing strings:

```
node scripts/i18n.js template
node scripts/i18n.js check fr
```

`scripts/i18n.js` only scans `app.js`, `main.js`, `covers.js`, `index.html`, and Pocket's own `pocket/www/index.html` and `pocket/www/pocket-bridge.js`. A new string in another file will not enter the template until that list includes it. Pocket's page marks its words with the same `data-i18n*` attributes as the desktop's, and its ⋯ sheet and bridge use `t()`.

Details, plural forms, and regional fallback (`fr-CA` → `fr` → English) are in [TRANSLATING.md](TRANSLATING.md). Quotation marks follow the spellcheck language (`QUOTE_STYLES` in `app.js`). Import chapter detection is `CHAPTER_WORDS` in `main.js`. Cover small-words are `CONNECTORS` in `covers.js`.

Italian has no spellcheck dictionary: the only Hunspell package on npm is GPL-3.0-only, and NEO is MIT. Do not add it.

## Pocket

`pocket/` is a Capacitor app that runs the desktop editor. Its bridge (`pocket/www/pocket-bridge.js`) implements `window.neo` against the phone's library folder. Android shares `Documents/NEO Library` via sync. iOS uses the app folder, optionally iCloud, with `LibraryHome.swift` locating that folder.

`scripts/pocket-www.js` (run by CI, and by hand before a local build) copies `app.js`, `covers.js`, `recording.js`, `recording-files.js`, `history-worker.js`, `styles.css`, `i18n.js`, `fonts/`, `locales/`, Hunspell's browser build, and the `SPELL_LANGUAGES` dictionaries from `main.js` into `pocket/www/`. Pocket's checker is `pocket/www/pocket-spell.js`, a module worker with the same messages as `spell-worker.js`. Writing History's `rec*` methods are in the bridge: its `recIO` reaches the library through Capacitor Filesystem, and `@data/…` paths reach the app's own folder, which holds what the desktop keeps in `userData` (the device id, `recording-cache/`). Pocket makes no backups and mirrors no sessions. `scripts/pocket-recording.test.js` runs the bridge and its worker against the desktop's results. A change to those files changes Pocket. Pocket-only behavior belongs in `pocket-bridge.js` or the native projects, not behind a desktop-only branch scattered through `app.js`.

None of these is an npm script.

## Handing changes to Hugh

Hugh pushes and releases himself and isn't a git user. Hand him work as a git bundle of main..your-branch, built on the latest origin/main, then tell him: save it to Downloads, `npm run bundle`. To ship a desktop release: `npm run release`. Both commands check their footing and stop with a plain sentence instead of half-finishing. Don't give him raw git or npm version steps when these cover it.

## When you change something

- A new filesystem operation needs a handler, a `libName()` boundary, and a `preload.js` method. Match the existing IPC names (`library:`, `book:`, `chapter:`, `aux:`, `json:`, `cover:`, `rec:`, `proof:`).
- A change to a chapter's HTML goes through `setChapterHTML(chId, html, cause)` (or `syncChapter(body, chId, cause)`), never `chapterHTML[id] =`. The recorder (**RECORDING** in `app.js`) keeps every change; `persistChapter` logs anything that skipped it as `unobserved`, and `npm run test:recording` fails on one.
- A new writer-visible string needs `t()` and a template refresh.
- A new way to remove text needs a recovery path and a sentence in the UI that says where the words went.
- Export formats are assembled in `app.js` and written by `export:save` in `main.js`. EPUB is a zip built in memory. PDF is printed from temporary HTML.
- Errors in the main process are appended to `neo-errors.log` via `logError`. Renderer failures go through `window.neo.logError`. Do not swallow a save failure; `persistChapter` rolls `savedHTML` back so the next flush retries.
